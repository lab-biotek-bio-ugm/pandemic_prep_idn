Supplementary Material: IUPAC Degeneracy Audit

A detailed biochemical validation appendix for Candidate 1 primers & probe

NotePurpose of this Appendix

This supplementary document provides a granular, nucleotide-by-nucleotide audit of the degenerate IUPAC positions within the designed primers and probe for Candidate 1 (designed under the Indonesia Only evolutionary model). All figures are derived directly from the Multiple Sequence Alignment (MSA) of Indonesian H5N1, H3N2, and H1N1 isolates, and are recorded in the raw database: Download Raw Entropy Profile TSV (entropy_profile.tsv)

1. IUPAC Degeneracy Decision Rules

In our pipeline, designed primers are back-mapped to the alignment consensus. Ambiguity codes (degeneracy) are selected using a strict minor-allele frequency (MAF) cutoff:

  1. Unambiguous Base (A/T/G/C): If a single base occurs at a frequency \(> 85\%\) (minor alleles \(< 15\%\)) at a given position, it is written as a standard nucleotide. Minor variations under \(15\%\) are ignored to prevent excessive degeneracy multipliers.
  2. Degenerate Base (IUPAC): If two or more nucleotides at a single position each clear the \(15\%\) threshold, the position is mapped to the appropriate IUPAC degeneracy code (e.g., R for A/G, Y for C/T, D for A/G/T).

1.1. Understanding the Degeneracy Multiplier

A degenerate primer is not a single sequence, but a physical mixture of multiple unique primer sequences synthesized together in the same tube. The Degeneracy Multiplier (e.g., 16x) represents the total number of unique sequence combinations resulting from the IUPAC positions in the primer.

It is calculated by multiplying the number of possible bases at each degenerate position: \[M = \prod_{i=1}^{L} \text{options}(c_i)\]

Where:

  • Standard bases (A, T, G, C) have 1 option.
  • Two-base degeneracies (R, Y, W, S, K, M) have 2 options.
  • Three-base degeneracies (B, D, H, V) have 3 options.
  • Four-base degeneracies (N) have 4 options.

For example, a forward primer with sequence CTGACTAARGGRATTTTRGGRTTTGTATTCA has four R positions (each allowing A or G). This results in a multiplier of \(2 \times 2 \times 2 \times 2 = 16\text{x}\). Thus, the final tube contains exactly 16 distinct primer variations in equal proportions (Linhart and Shamir 2005).

Why limit the multiplier?

  • Primer Dilution Effect (Chassalevris et al. 2020): Since a degenerate primer pool is a physical mixture of many different sequences, the concentration of the specific primer variant that matches a patient’s viral strain is significantly lower than the total primer concentration. If the degeneracy multiplier is too high, the effective concentration of the matching variant drops below the threshold required for efficient hybridization, leading to a loss of diagnostic sensitivity.
  • Non-Specific Amplification & Competition: High degeneracy increases the pool complexity, raising the risk of off-target binding to the host genome and primer-dimer formation. The excess non-matching sequences can also compete for enzyme binding, reducing reaction efficiency.

To balance universality (broad coverage) and sensitivity, the pipeline enforces a maximum degeneracy limit of \(16\text{x}\) for RAA designs.

5. Automated Supplementary Excel Exporter Tool

To export full executive and detailed supporting workbooks for laboratory synthesis and supplementary submission, use scripts/export_supplementary.py:

# Export all active target builds (auto-detected from results/):
python scripts/export_supplementary.py \
  --results-dir results \
  --outdir supplementary \
  --only-degenerate

# Export a specific subset (e.g. exclude a build by its target token):
python scripts/export_supplementary.py \
  --results-dir results \
  --outdir supplementary \
  --only-degenerate \
  --exclude-targets influenza-b

# Alternatively, restrict to specific target YAML config files:
python scripts/export_supplementary.py \
  --results-dir results \
  --outdir supplementary \
  --only-degenerate \
  config/config_influenza_a_mp.yaml config/config_influenza_b_mp.yaml

Generated Workbooks Package

  1. Executive_Summary_Diagnostic_Assays.xlsx: Overview, Oligo Synthesis Orders (Best + 3 Alternatives), Pairwise/N-Plex compatibility, BLAST summary, the per-hit Human Off-Target Risk Audit (sheet 05), and the cited QC Decision Audit (sheet 06).
NoteHow ‘BEST RECOMMENDED’ is assigned

The recommendation label on the ordering sheet comes from the selection verdict, not from list position. A combination that failed the selection gates is labelled NOT RECOMMENDED even if it sorted first — it is never shown as BEST just because it is rank 1. (Implemented by recommendation_category() in scripts/export_supplementary.py; if the quality floors had to be relaxed to find any candidate, the label says so, e.g. “relaxed to L1”.)

  1. S1_Primer_Candidates.xlsx: Granular candidate metrics for each target build.
  2. S2_BLAST_Specificity.xlsx: Off-target BLAST specificity details.
  3. S3_Multiplex_Compatibility.xlsx: N-Plex thermodynamic cross-dimer screening.
  4. S4_QC_Summary.xlsx: Sequence retention & QC stats.
  5. S5_Conservation_Scoring.xlsx: Entropy and conservation grades.

6. Per-Assay QC Decision Dossier

For surveillance use, each recommended assay carries a standalone, auditable dossier. It is generated from the same run artifacts (nothing is recomputed) and is emitted alongside the workbooks, into supplementary/qc_dossier/ (or, in the batch orchestrator, --outdir/qc_dossier/):

python scripts/qc_dossier.py \
  --results-dir results \
  --out supplementary/qc_dossier \
  --top-n 5

Open qc_dossier/index.html for the list of assays. Each dossier is a self-contained HTML page (plus a markdown mirror) covering, per assay:

  • Coverage audit — the design/focal figure and the surveillance/global figure side by side, with a per-subtype breakdown so a lineage-specific hole is visible rather than hidden in the average. The selection gate judges the global figure; both are shown so the distinction is explicit.
  • Human off-target audit — every human hit spelled out (accession, organism, identity, mismatch, 3’-overhang, % bound), each classified against the never-relaxed FATAL_HIT gate with the specific reason it is tolerated, plus the pair-level amplicon count — i.e. exactly why a “grade A” candidate that still matches human sequence is safe.
  • Decision tree — every go/no-go gate: value → threshold → verdict → rationale → literature citation, from qc/decision_criteria.yaml (the single, cited source of truth, kept in lock-step with the code by tests/contracts/test_decision_registry.py).

The dossier is a generated artifact and is not committed; regenerate it from a run’s results/ with the command above.
